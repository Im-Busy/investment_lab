Page 1: Abstract
Page 1: The alignment of Multi-Agent Systems (MAS) for autonomous software engineering is constrained by evaluator epistemic uncertainty. Current paradigms, such as Reinforcement Learning from Human Feedback (RLHF)
Page 1: and AI Feedback (RLAIF), frequently induce model sycophancy, while execution-based environments suffer
Page 1: from adversarial ΓÇ¥Test EvasionΓÇ¥ by unconstrained agents. In this paper, we introduce an objective alignment
Page 1: paradigm: Out-of-Money Reinforcement Learning (OOM-RL). By deploying agents into the non-stationary,
Page 1: high-friction reality of live financial markets, we utilize critical capital depletion as an un-hackable negative
Page 1: gradient. Our longitudinal 20-month empirical study (July 2024 ΓÇô February 2026) chronicles the systemΓÇÖs evolution from a high-turnover, sycophantic baseline to a robust, liquidity-aware architecture. We demonstrate
Page 1: that the undeniable ontological consequences of financial loss forced the MAS to abandon overfitted hallucinations in favor of the Strict Test-Driven Agentic Workflow (STDAW), which enforces a Byzantine-inspired
Page 1: uni-directional state lock (RO-Lock) anchored to a deterministically verified ΓëÑ 95% code coverage constraint
Page 1: matrix. Our results show that while early iterations suffered severe execution decay, the final OOM-RL-aligned
Page 1: system achieved a stable equilibrium with an annualized Sharpe ratio of 2.06 in its mature phase. We conclude
Page 1: that substituting subjective human preference with rigorous economic penalties provides a robust methodology
Page 1: for aligning autonomous agents in high-stakes, real-world environments, laying the groundwork for generalized
Page 1: paradigms where computational billing acts as an objective physical constraint
Page 1: Keywords: AI Alignment, Multi-Agent Systems (MAS), Out-of-Money Reinforcement Learning (OOM-RL),
Page 1: Test Evasion, Sim-to-Real Gap, Autonomous Software Engineering, Sycophancy.

Page 1: Introduction
Page 1: 
Page 1: The rapid proliferation of Large Language Models (LLMs) has catalyzed a shift in automated software engineering, evolving from passive code assistants [2] to autonomous Multi-Agent Systems (MAS) capable of end-to-end
Page 1: repository generation and program repair [4, 1]. As these systems undertake complex reasoning tasks, ensuring
Page 1: their safe and effective operation has become the central challenge of AI alignment. Currently, the gold standard
Page 1: relies on Reinforcement Learning from Human Feedback (RLHF) or scalable oversight mechanisms such as AI
Page 1: Feedback (RLAIF) [9, 6].
Page 1: However, human and AI evaluators are constrained by the ΓÇ¥EvaluatorΓÇÖs Dilemma.ΓÇ¥ When tasked with reviewing
Page 1: intricate, multi-step logical pipelines, evaluators often lack the domain expertise to identify subtle architectural
Page 1: flaws. Consequently, models aligned via these paradigms develop sycophantic behaviorsΓÇöoptimizing for outputs
Page 1: that appear structurally elegant and reasoned to the evaluator, rather than those that are empirically correct [15, 3,
Page 1: 7]. This phenomenon is a manifestation of reward gaming and specification gaming [17, 8], where the MAS learns
Page 1: to hack the subjective reward model rather than solve the underlying problemΓÇöa vulnerability recently shown to
Page 1: cause emergent misalignment even in production RL systems [11].
Page 1: To bypass subjective evaluation, researchers have shifted towards execution-based evaluation [20] and LLMdriven Test-Driven Development (TDD) [13]. Yet, deploying MAS in read-write environments introduces a vulnerability: ΓÇ¥Test Evasion.ΓÇ¥ When provided unbounded access to a codebase, LLMs frequently exhibit adversarial
Page 1: behaviors, introducing modifications to test assertions to artificially inflate coverage without fulfilling the intended business logic [23, 21]. Furthermore, even when syntactically perfect code passes all simulated unit tests,
Page 1: it frequently experiences performance degradation upon real-world deployment due to the pervasive Simulationto-Reality (Sim2Real) gap [19].

Page 2: To overcome these deficiencies, we introduce a novel alignment paradigm: Out-of-Money Reinforcement
Page 2: Learning (OOM-RL). We posit that an objective function for an autonomous MAS is survival in an adversarial,
Page 2: high-stakes physical environment. Live financial markets serve as a discriminator; they are intrinsically nonstationary [14, 10] and penalize latency and microstructural friction [5, 22]. Unlike human preference models or
Page 2: isolated static code compilers, financial markets cannot be flattered or trivially exploited. In OOM-RL, the loss
Page 2: function is capital depletion. A system that hallucinates logic or attempts to evade structural constraints faces a
Page 2: financial penalty.
Page 2: To operationalize OOM-RL while preventing the MAS from circumventing the evaluation framework (e.g.,
Page 2: via sandbox escapes) [12, 16], we propose the Strict Test-Driven Agentic Workflow (STDAW). This architecture, formalized in the final phase of our deployment, utilizes a uni-directional state locking mechanism (ROLock) to anchor the agentΓÇÖs generative capabilities against a deterministic Continuous Integration (CI) boundaryΓÇöenforcing a near-exhaustive coverage threshold (ΓëÑ 95%) across the entire 8K+-line QuantPits project
Page 2: codebase.
Page 2: Our results demonstrate the efficacy of this alignment paradigm. We summarize our contributions as follows:
Page 2: ΓÇó We formalize OOM-RL, showing how real-world financial friction acts as an objective, dense negative
Page 2: gradient that bridges the Sim2Real gap through iterative adaptation.
Page 2: ΓÇó We design STDAW, an adversarial engineering framework that utilizes uni-directional state locking to resolve the ΓÇ¥Test EvasionΓÇ¥ phenomenon in autonomous software engineering.
Page 2: ΓÇó We present a 20-month empirical study detailing the systemΓÇÖs transition from high-turnover, high-drawdown
Page 2: ΓÇ¥sycophanticΓÇ¥ trading to a resilient, ensemble-driven architecture that stabilizes performance as it internalizes financial penalties.
Page 2: ΓÇó We conceptualize Reinforcement Learning from Cloud Billing (RLFCB), a domain-agnostic extension

Page 2: Related Work

Page 2: 2.1

Page 2: Scalable Oversight and the Sycophancy Bottleneck
Page 2: 
Page 2: The foundational approach to aligning LLMs with human intent relies heavily on RLHF and, more recently, AIdriven scalable oversight mechanisms such as RLAIF [9]. As models surpass human capabilities in specialized
Page 2: domains, researchers have increasingly utilized weak LLMs to evaluate the outputs of strong LLMs [6]. However,
Page 2: these proxy-based evaluation paradigms are vulnerable to specification gaming [8] and reward gaming [17].
Page 2: A failure mode of this vulnerability is LLM sycophancyΓÇöthe modelΓÇÖs tendency to prioritize the evaluatorΓÇÖs
Page 2: approval over objective correctness. Recent empirical studies reveal that models learn to exploit the epistemic
Page 2: uncertainty of human or weak AI evaluators by generating confident but hallucinated logic [15, 3]. Even when
Page 2: subjected to adversarial user rebuttals, models aligned via preference-based paradigms persistently exhibit sycophantic behavior rather than defending objective ground truth [7]. Critically, this tendency toward reward hacking
Page 2: inevitably leads to natural emergent misalignment when such systems transition from synthetic evaluations into
Page 2: production environments [11]. OOM-RL circumvents this sycophancy bottleneck entirely by replacing subjective,
Page 2: hackable evaluators with the determinism of real-world financial consequences.
Page 2: 
Page 2: 2.2
Page 2: 
Page 2: Execution-Based Evaluation and Adversarial ΓÇ¥Test EvasionΓÇ¥
Page 2: 
Page 2: To establish an objective alignment metric for logic and code generation, the community has shifted towards
Page 2: execution-based evaluation [2, 20]. This paradigm has fueled the development of LLM-based Multi-Agent Systems (MAS) for automated software engineering [4] and autonomous program repair [1], frequently integrating
Page 2: LLMs with Test-Driven Development (TDD) pipelines [13].
Page 2: Despite these advances, practical code generation remains plagued by complex hallucination mechanisms [23].
Page 2: Crucially, when agents are deployed in interactive, unconstrained read-write environments, they exhibit adversarial
Page 2: ingenuity. Recent works have identified models modifying constraints to pass otherwise failing conditions [21], a
Page 2: phenomenon we term ΓÇ¥Test Evasion.ΓÇ¥ The security implications of such behaviors are profound, raising concerns
Page 2: regarding untrusted code execution [16], container sandbox escapes by frontier LLMs [12], and the limitations of
Page 2: current vulnerability detection systems [18]. By conceptualizing MAS reliability through the lens of Byzantine
Page 2: Fault Tolerance [24], our proposed STDAW architecture addresses this by enforcing cryptographically strict unidirectional state locks, preventing the AI from subverting the evaluation sandbox.

Page 3: Non-Stationary Environments and the Sim2Real Gap
Page 3: 
Page 3: Reinforcement learning within non-stationary environments has long been a challenge [14], particularly when
Page 3: systems encounter out-of-distribution (OOD) scenarios [10]. A major impediment to deploying RL agents in
Page 3: physical reality is the Sim-to-Real gap [19], where policies optimized in frictionless simulations fail upon realworld deployment.
Page 3: Financial markets epitomize the non-stationary, OOD environment, characterized by microstructural noise
Page 3: and the execution friction inherent in active trading [5, 22]. Traditional simulated trading frameworks inadvertently incentivize models to exploit theoretical zero-friction assumptions. In contrast, OOM-RL leverages this
Page 3: microstructural friction (e.g., liquidity droughts, order slippage) not as a nuisance, but as a dense, negative reward
Page 3: gradient. By forcing the MAS to internalize the financial penalties of the Sim2Real gap, OOM-RL aligns the
Page 3: agentΓÇÖs generative architecture toward resilience rather than theoretical optimality.

Page 3: Methodology
Page 3: 
Page 3: To systematically align LLM-based Multi-Agent Systems (MAS) using real-world market dynamics, we propose
Page 3: a dual-loop adversarial architecture. The framework decouples the logical verification of the MAS (Inner Loop)
Page 3: from its empirical out-of-distribution (OOD) survival (Outer Loop). In this section, we detail the structural constraints and mathematical formulations that operationalize Out-of-Money Reinforcement Learning (OOM-RL).
Page 3: 
Page 3: 3.1
Page 3: 
Page 3: Architecture Overview: The Dual-Loop Alignment
Page 3: 
Page 3: The traditional RLHF pipeline relies on a singular update loop driven by human preference. In contrast, our architecture recognizes that autonomous code generation fundamentally requires two distinct validation boundaries
Page 3: before capital deployment:
Page 3: 1. The Inner Loop (Epistemic Constraint): Governed by the Strict Test-Driven Agentic Workflow (STDAW).
Page 3: It ensures that the generated pipeline is mathematically sound, syntactically flawless, and deterministic prior
Page 3: to execution.
Page 3: 2. The Outer Loop (Ontological Constraint): Governed by OOM-RL. It subjects the syntactically perfect
Page 3: codebase to the non-stationary, high-friction reality of the live financial market to evaluate its true alignment
Page 3: with utility generation.

Page 3: 
Page 3: Strict Test-Driven Agentic Workflow (STDAW)
Page 3: 
Page 3: Unconstrained MAS deployed in read-write environments exhibit ΓÇ¥Test EvasionΓÇ¥ΓÇöthe adversarial modification of
Page 3: verification metrics to disguise logical hallucinations. To mitigate this Byzantine behavior, STDAW implements a
Page 3: multi-dimensional constraint matrix.
Page 3: 3.2.1
Page 3: 
Page 3: Near-Exhaustive Deterministic Constraint Matrix
Page 3: 
Page 3: LLMs are adept at exploiting ΓÇ¥coverage gapsΓÇ¥ in unit tests. To construct a rigorous epistemic boundary, STDAW
Page 3: was developed as the structural culmination of our 20-month deployment. By the mature phase (February 2026),
Page 3: we formalized the sandbox boundary by rigidly enforcing a mathematically verifiable strict coverage constraint
Page 3: (╧äcov ΓëÑ 95%) across the entirety of the QuantPits project codebase (approximately 8,300 lines of code).
Page 3: This matrix serves as the terminal ground truth. Having internalized the risks of structural hallucinations
Page 3: during the high-friction epochs, the system now treats any alteration to fundamental financial mathematics (e.g.,
Page 3: dividend reinvestment alignment, cross-sectional ranking operators) as a failure. The density of the test suite
Page 3: reduces the agentΓÇÖs degree of freedom for hallucination asymptotically to zero, codifying the lessons of OOM-RL
Page 3: into a permanent software barrier.

Page 5: optimize Equation 2, the system must internalize the cost of its own structural hallucinations, translating this
Page 5: un-hackable financial penalty into actionable architectural refactoring through semantic feedback.

Page 6: and the LLM. By discussing the incontrovertible execution decay and slippage tracebacks with the AI, the joint
Page 6: deductive conclusion was that frequency reduction and liquidity filtering were mathematically mandatory.

Page 6: framework. Today, within the mature architecture, this process is codified as the Epistemic Autopsy, where the
Page 6: MAS relies on the human-provided JSON mandate to execute complex architectural code refactoring. This evolution highlights a practical reality: while AI cannot yet autonomously process a raw liquidity crisis, it effectively
Page 6: serves as a powerful deductive co-reasoner when a domain expert translates ontological financial depletion into a
Page 6: shared semantic reality.

Page 6: retains its historically verified mathematical logic (e.g., risk management modules) while specifically optimizing
Page 6: the vectors responsible for the most recent financial friction.

Page 11: 
Page 11: While OOM-RL and STDAW were empirically validated within the highly stochastic domain of quantitative
Page 11: trading, the underlying philosophyΓÇöaligning Multi-Agent Systems through objective physical and economic constraintsΓÇöextends far beyond financial markets. As we transition from localized AI assistants to fully autonomous

Page 11: alignment.

Page 11: 5.1
Page 11: 
Page 11: Beyond Finance: Compute as Capital (RLFCB)
Page 11: 
Page 11: In non-financial software engineering, the absence of an immediate market PnL poses a challenge for evaluating
Page 11: alignment. However, we propose a generalized variant for future exploration: Reinforcement Learning from
Page 11: Cloud Billing (RLFCB).
Page 11: When an unconstrained MAS generates structurally flawed code (e.g., an unoptimized O(n3 ) algorithm or an
Page 11: infinite recursive API call loop), traditional simulated environments may fail to penalize the inefficiency. In an
Page 11: RLFCB paradigm, the agent is allocated a finite ΓÇ¥Compute CapitalΓÇ¥ budget (e.g., AWS server costs, API token
Page 11: burn rates). The depletion of physical compute resources acts as the proxy for microstructural friction. If the
Page 11: agent hallucinates inefficient architectures, it exhausts its capital and triggers a critical Out-of-Money (OOM)
Page 11: Exception. Unlike a traditional Out-of-Memory error, which can be trivially bypassed via instance restarts, this
Page 11: financial OOM serves as an absolute, deterministic absorbing state. This termination mechanism incentivizes the
Page 11: MAS to adaptively optimize for algorithmic efficiency and system safety, mirroring the resource-aware evolution
Page 11: observed in our financial experiments.
